# Themes, step 5: family-job-tracking – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The job tracker changes from its plain dark slate look to the family look (Aurora, from
`family-hub-theme`) and shows the person's theme from the hub.

**Architecture:** As the budget, meal-planer and planner steps, with two differences: the app had no Aurora yet, so
its shared classes in `frontend/src/ui.ts` move to the package's components (`CARD` → `glass-card`, `BUTTON` →
`btn-primary`, fields as the hub's); and its schema changes go through `backend/app/upgrade.py` (no Alembic).

**Tech Stack:** FastAPI, SQLAlchemy, pytest; React 19, Vite 8, Tailwind v4, Playwright.

**Spec:** `family-hub/docs/superpowers/specs/2026-11-28-themes-design.md`.

## Global Constraints

- Package `theme-v1.0.0` release URL; client `family-hub-client` at `7a9848864c6fad37f791f8ed0f3d4521c4276936` (1.2.0).
- No palette classes, hex or `rgba()/hsl()` in `.tsx`; `check-colors.mjs` (planner's copy) in `lint`.
- Lessons: text-page on (nearly) solid light fills (/70+ too); near-opaque surfaces → `bg-page/<opacity>`, covering
  translucent ones blurred; polled blur checks; no tests locating by colour classes; hovers never equal to base.
- The look changes on purpose (to Aurora); before/after screenshots of the list, an application, the inbox and
  settings, phone and desktop, in the PR.

## Review Focus

1. Hub sends no or an unknown theme → `aurora`.
2. An existing database gets `users.theme` on start (`upgrade.py`), twice is harmless.
3. Status badges (sent, interview, offer, rejected, ...) stay distinguishable from each other.
4. Primary vs secondary vs danger buttons stay distinguishable; the danger action stays red.
5. Unread/new counts and badges stay readable (text on solid fills).
